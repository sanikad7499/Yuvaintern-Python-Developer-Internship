# 🌱 GreenLife – Sustainability Tracker

**GreenLife** is a Python-based web application that helps users track their daily electricity consumption and travel activities while estimating their carbon footprint. It provides a simple dashboard to understand environmental impact through activity records, summary cards, and interactive charts.

##  Project Overview

GreenLife aims to encourage sustainable habits by making users aware of the estimated carbon emissions generated by their everyday activities.

Users can add activities, view their carbon footprint, monitor monthly statistics, and manage their activity history through an easy-to-use dashboard.

##  Features

- **Dashboard:** Displays monthly carbon emissions and activity statistics.
- **Add Activity:** Record electricity consumption and travel activities.
- **Carbon Footprint Calculation:** Estimates CO₂ emissions using predefined emission factors.
- **Interactive Charts:** Visualises category-wise emissions and six-month emission trends.
- **Activity History:** Displays recently recorded activities.
- **Delete Activity:** Allows users to remove unwanted activity records.
- **Input Validation:** Checks activity type, amount, date, and description.
- **Responsive Interface:** Provides a clean and user-friendly dashboard.

##  Carbon Emission Calculation

The application estimates carbon emissions using the following formula:

**Estimated CO₂ Emissions = Activity Amount × Emission Factor**

The project uses the following illustrative emission factors:

| Activity | Emission Factor |
|---|---:|
| Electricity | 0.70 kg CO₂e/kWh |
| Car | 0.18 kg CO₂e/km |
| Two Wheeler | 0.10 kg CO₂e/km |
| Bus | 0.08 kg CO₂e/km |
| Train | 0.04 kg CO₂e/km |

*Note: These factors are illustrative assumptions used for this educational project. They are not verified official emission factors. Actual emissions may vary depending on location, vehicle type, energy source, and other conditions.*

##  Database Structure

GreenLife uses SQLite to store user activity records.

**Table: `activities`**

| Column | Description |
|---|---|
| id | Unique activity ID |
| activity_type | Type of activity |
| amount | Consumption or distance |
| activity_date | Date of activity |
| notes | Additional description |
| co2_kg | Estimated carbon emissions |

##  Input Validation and Data Handling

The application includes server-side validation to improve data accuracy and reliability.

- Accepts only supported activity categories.
- Rejects zero, negative, and non-numeric amounts.
- Checks for invalid and future dates.
- Limits the description length.
- Uses parameterized SQL queries for database operations.
